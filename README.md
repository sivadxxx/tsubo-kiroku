# ツボ記録

来院ごとに使ったツボを、あらかじめ用意したリストから選んで記録するアプリです。
記録がたまると、「症状ごとの効いたツボ」が集計されます。

問診票と手書きのメモは、これまでどおり GoodNotes に残します。iPad では Split View で GoodNotes と並べて使います。

## 使い方

1. **患者を追加**：「記録」→「患者を追加」で、カルテの番号（No）を登録します。
   氏名・住所・電話番号はこのアプリに入れません。GoodNotes の問診票の「No」の欄に、同じ番号を書いておきます。
2. **施術を記録**：患者を開いて「今日の施術を記録」。
   - 日付の下の「担当者」で、施術を担当した人を選べます（選ばなくてもかまいません）。「＋」で、その場で担当者を足せます。
     次に記録するときは、その患者の前回の担当者（なければ、その端末で最後に選んだ担当者）が最初から入ります。
   - 「症状を選ぶ」で、今日みる症状を選びます（次回からは前回の症状が最初から入ります）。
   - 「ツボを選ぶ」で、ツボの右にある L・R・両・中 のどれかを押すと、その場で記録に入ります。
     リストにないツボは、名前を入れて「ツボのリストに追加」を押すと、その場で足せます。
     並びは、右上で「効いた順」（その症状で効いた回数・よく使う回数の多い順）と「リストの順」（「リスト」で並べた順）を切り替えられます。
   - ツボごとに、ねらい（任意）と効果（◎ よく効いた・○ 効いた・△ 少し変化・× 変化なし）を入れます。
   - 症状を2つ以上選んだときは、ツボごとに「どの症状に対して」を選べます。
   - 入力はそのつど自動で保存されます。
3. **統計**：症状を選ぶと、その症状に使ったツボが「効いた回数」の多い順に並びます。
   「効いた」は ◎ と ○ の合計、割合は効果を入れた回数に対するものです。期間と並び順は変えられます。
   担当者を2人以上登録していると、担当者でしぼれます。
   「ツボごとの効いた症状」に切り替えると、逆向き（このツボはどの症状に効いたか）で見られます。
   「ツボランキング」に切り替えると、すべてのツボが、使った回数の多い順に並びます（同じ回数のツボは同じ順位）。
   期間は 今日・今週（月曜〜日曜）・今月・今年・全期間から選べます。「‹」「›」で前の期間にさかのぼれます（きのう、先週、先月、など）。
4. **リスト**：ツボ・症状・担当者のリストを足す・直す画面です。「まとめて追加」は、1行に1つ書いて一度に登録できます
   （ツボは「名前, よみ, グループ」とカンマで区切ると、よみとグループも入ります）。
   使わなくなったものは「使わない」にすると、選ぶ画面から消えます（過去の記録と統計には残ります）。
   右のつまみ（≡）を上下に引くと、並べ替えられます。並べた順は、ツボ・症状・担当者を選ぶ画面の並びになります
   （症状は、その患者で使ったことのあるものが先。ツボは「リストの順」にしたとき）。
   分けて登録した症状を1つにしたいとき（例：「〜 右」と「〜 左」を「〜」に）は、症状を開いて「ほかの症状にまとめる」を押し、まとめる先を選びます
   （名前を、すでにある症状と同じ名前に変えて保存しても、まとめられます）。過去の記録と統計は、まとめた先の症状のものになります。元には戻せません。

## 問診の録音（AI で文字にしてまとめる）

問診の会話を iPad のマイクで録音し、OpenAI の AI で文字にして、見出しごとに整理します。まとめは、その日の来院の記録に残ります。

1. **キーを入れる（端末ごとに1回）**：OpenAI の管理画面で API キーを作り、「設定」→「問診の録音（AI）」に貼り付けて「保存」。
   「つながるか試す」で、キーが使えるかを確かめられます（費用はかかりません）。
   キーはその端末の中だけに保存され、クラウド・控え・CSV には入りません。iPad・iPhone など、使う端末ごとに入れてください。
2. **録音する**：来院の記録の「問診の録音」で「録音を始める」。最初の1回だけ、確認が出ます。
   **会話は OpenAI に送られるので、患者さんの同意を得てから始めてください。**
   - 録音中も、ツボ選びなどの入力や、ほかの画面への移動ができます。ほかの画面では、下に「録音中　記録にもどる」の帯が出ます。
   - 録音中は画面が消えないようにしています。アプリを閉じたり、ほかのアプリを前に出したりすると、録音が止まることがあります。
   - 「取り消す」で、いまの録音を捨てられます。
3. **止めてまとめる**：文字にして（数分ごとの区切りを順に）、まとめを作ります。終わると、まとめが出て自動で保存されます。
   - まとめは、そのまま書き直せます（自動で保存）。「まとめなおす」で、文字起こしの全文から作り直せます（手で直した内容は消えます）。
   - 「続きを録音する」と、文字起こしは前の全文のあとに足され、まとめは全文から作り直されます。
   - 「文字起こしの全文」は、開くと読めます。「全文を消す」で全文だけを消せます（まとめは残ります）。
   - 電波がない・キーが違うなどでうまくいかなかったときは、録音は端末の中に残ります。その来院を開いて「もう一度ためす」。
     録音は、まとめを保存できたら端末から消えます。
4. **GoodNotes へ送る**：まとめを PDF（A4）にして共有の画面を出すので、GoodNotes を選びます（パソコンではダウンロードになります）。
   ファイル名は `問診_日付.pdf` で、患者の名前は入りません（PDF の1ページ目には、患者の表示名と何回目かが入ります）。
   「コピー」は、まとめの文章だけをコピーします。
5. **まとめ方を変える**：「設定」→「まとめ方の指示」を書き換えると、まとめ方が変わります。「はじめの指示にもどす」で元に戻せます。
   整理に使う AI は、`gpt-6.2-sol`（標準）・`gpt-6.1-terra`（安い）・`gpt-6.2-astra`（高性能・高い）から選べます。
   文字起こしは、話者を分けられる `gpt-4o-transcribe-diarize` を使います。

**費用と注意**
- 費用の目安は、10分の録音で 15円前後です（OpenAI の利用料。整理に使う AI で変わります）。OpenAI の管理画面で、月の上限額を決めておくと安心です。
- 患者の氏名などは、まとめに書かないよう AI に指示していますが、会話そのものは OpenAI に送られます。まとめは必ず目で確かめてください。
- まとめは聞き間違いを含むことがあります。あやしいところには「（聞き取り不確か）」と付くように指示しています。

## 場所を分ける（治療院・病院など）

- 「記録」の上にあるボタンで、場所を切り替えます。患者は場所ごとに分かれます。「＋ 場所」で場所を足せます。
- 場所ごとに、患者の管理のしかたを選べます。
  - **番号で管理**：カルテの番号（No）と呼び名で登録します。氏名は入れません。
  - **名前で管理**：患者の名前（と、よみ）で登録します。カルテの番号がない場所で使います。
- 担当者は場所ごとに分かれます。来院の記録では、その患者の場所に出ている担当者だけが並びます。
  「リスト」→「担当者」でその人を開くと、出ている場所をいくつでも選べます。「すべての場所」にすると、どの場所でも選べます。
- ツボと症状のリストは、すべての場所で共通です。統計は、すべての場所を合わせても、場所ごとにしぼっても見られます。
- 場所の名前や管理のしかたは、「リスト」→「場所」で変えられます。
- 名前で管理する場所の患者名は、この端末の中（ログインしているときはクラウド）と、書き出した控え・CSV のファイルに入ります。ファイルの置き場所や渡す相手に注意してください。

## 記録の保存と同期

- **ログインしていないとき**：記録は、使っている端末の中だけに保存されます（ほかの端末とは共有されません）。
- **ログインしているとき**：記録はクラウド（Google の Firebase）に保存され、同じログインの iPad・iPhone・Mac で同じ記録になります。
  - 「設定」→「同期」で、ツボマップ3D の管理者と同じメールアドレスとパスワードでログインします。端末ごとに1回だけです。
  - ログインしたとき、その端末に入っていた記録はクラウドに移り、ほかの端末の記録と1つにまとまります
    （同じ名前の場所・ツボ・症状・担当者は1つにまとめます）。クラウドに届いたことを確かめてから、端末の中の記録を消します。
  - 電波がないときも使えます。記録は端末にためておき、つながったときに送ります。
  - 読み書きできるのは、ログインした本人（管理者）だけです。ツボマップ3D の名簿にいるほかの人は見られません。
  - ログアウトすると、その端末では記録が見られなくなります（クラウドには残り、もう一度ログインすると戻ります）。
- 「設定」→「控えを書き出す」で、すべての記録を1つのファイルにできます。「控えを読み込む」で戻せます（いまの記録は残したまま足します）。
  ログインしていないときは、端末の故障や買い替えに備えて、ときどき書き出してください。
- 「CSV を書き出す」は、ツボ1つを1行にした一覧です。Excel や Numbers で自由に集計できます。

### 同期のための、Firebase 側の設定（最初に1回だけ）

ツボマップ3D と同じ Firebase（プロジェクト `tsubomap3d`）を使います。Firebase の管理画面の「Firestore Database」→「ルール」に、次のかたまりを足して「公開」します
（`match /databases/{database}/documents {` の中、いちばん最後の `}` 2つの手前）。

```
    match /kiroku/{uid}/{kind}/{id} {
      allow read, write: if hasRole(['owner']) && request.auth.uid == uid;
    }
```

## 作りについて

- `index.html`（画面と見た目）・`app.js`（画面の動き）・`stats.js`（集計の計算）・`store.js`（端末の中への保存）
- `cloud-firebase.js`（ログインとクラウドへの保存）・`config.js`（Firebase の接続先。秘密の鍵ではありません）
- `monshin.js`（問診の録音と、OpenAI への問い合わせ）・`pdf.js`（まとめを PDF にする）
- `src/cloud-mock.js`：動作確認用のにせのクラウド。`http://localhost:…/?mock` で開いたときだけ使います（パスワードは `testpass1`）
- `src/ai-mock.js`：動作確認用のにせの AI。`?mock` で開いたときだけ使います
- `src/build.py`：アイコン・`manifest.webmanifest`・オフライン用の `sw.js` を作ります。
  `index.html` や `app.js` を直したあとは `python3 src/build.py` を実行します（端末側が新しい内容に入れ替わります）。
